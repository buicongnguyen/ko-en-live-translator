Setup guide

Two practical ways to run Korean-to-English live translation.

This guide explains how to build both versions: a local-network self-hosted GPU server with a web app, and a small local PC app that runs the model and browser interface on the same laptop.

Decision

Choose between two app shapes

Both versions use the same core pipeline. The difference is where the model runs and how browsers reach the audio backend.

Option A: LAN GPU server + web app

Best quality

The RTX 5090 PC runs FastAPI and the AI model. Laptops, phones, or tablets open the web app from the local network and stream microphone audio to the server.

Use this when you want the best Korean recognition and more stable translation with a larger model such as large-v3.

Option B: Local PC + browser interface

Small app

The laptop runs the backend and model locally. The browser UI opens at http://127.0.0.1:8000, captures the mic, and shows subtitles without another server.

Use this for portable offline translation. Start with small on weaker laptop GPUs, then move to medium only after checking VRAM and thermals.

Requirements

Minimum and recommended setup

These numbers separate official software minimums from practical live-translation recommendations. The app may start on weaker hardware, but live Korean-to-English subtitles need spare CPU, RAM, VRAM, and thermal headroom.

Case Minimum to start Recommended for useful live translation Notes and source
Browser client Modern Chrome, Edge, Firefox, or Safari; microphone permission; HTTPS or localhost. Headset or close microphone, quiet room, and same LAN as the server when using Option A. MDN documents that getUserMedia() requires a secure context such as HTTPS or localhost.
A1000-class local laptop NVIDIA driver, CUDA-capable GPU, 4 GB VRAM practical floor, Python 3.11/3.12 recommended, 8 GB system RAM. 8 GB VRAM, 16 GB system RAM, plugged-in power mode, small first, then medium if stable. OpenAI lists small at about 2 GB VRAM and medium at about 5 GB; leave extra room for Windows, browser, and buffers.
CPU fallback laptop x86-64 CPU with SSE 4.1 or ARM64, 8 GB RAM, base with CPU int8. 8+ CPU threads, 16 GB RAM, base or small; expect slower subtitle updates. CTranslate2 lists x86-64 SSE 4.1 and ARM64 CPU support; faster-whisper can run CPU int8.
RTX 5090 LAN server NVIDIA GPU with enough VRAM for large-v3; 16 GB system RAM; wired or strong Wi-Fi LAN. RTX 5090, 32 GB system RAM, Ethernet, large-v3, CUDA float16, HTTPS reverse proxy. NVIDIA lists RTX 5090 with 32 GB GDDR7; OpenAI lists large-class Whisper at about 10 GB VRAM.
Meeting/system audio helper Windows PC, microphone mode first, then WASAPI loopback for system audio. Desktop helper that captures Zoom, Teams, YouTube, or browser audio and sends PCM to the same backend. Microsoft's WASAPI loopback sample is the reference path for Windows system-audio capture.
Whisper model Official approximate VRAM Use in this project Practical guidance
base About 1 GB CPU fallback or very weak GPU testing. Fastest fallback, but Korean-to-English quality is limited.
small About 2 GB Default safe preset for A1000-class laptops. Best first test for low latency and low VRAM pressure.
medium About 5 GB Quality mode for 8 GB laptop GPUs. Use int8_float16, beam_size=1, and watch nvidia-smi.
large-v3 Large-class reference is about 10 GB Best fit for the RTX 5090 LAN server. Use on the server for better Korean recognition and translation stability.
turbo About 6 GB Not recommended for this Korean-to-English translation app. OpenAI notes turbo is not trained for translation tasks.
Minimum VRAM is not the same as smooth live translation. If the model barely fits, subtitles may lag, the GPU may throttle, or the app may fail when the browser and Windows also use GPU memory.

Terminology

Vocabulary for this setup

These terms appear in commands and error messages. Knowing them makes it much easier to decide whether a problem is audio, network, model quality, or GPU setup.

Term Plain meaning In this project
ASR Automatic speech recognition: speech into text. Whisper can transcribe Korean when task=transcribe.
Speech translation Speech in one language directly into text in another language. Whisper uses task=translate for Korean speech to English text.
VAD Voice activity detection: deciding when someone is speaking. Stops silence from being sent to the model and decides when a subtitle line is final.
WebSocket A long-running browser-to-server connection. The browser streams audio chunks and receives subtitle updates over /ws.
HTTPS / WSS Encrypted web page and encrypted WebSocket. Needed when a phone or another laptop opens the app from the LAN.
localhost / 127.0.0.1 The same computer you are using. Use this for the local laptop app: http://127.0.0.1:8000.
LAN Local area network: devices on your home or office Wi-Fi/router. The RTX server might be 192.168.1.50; clients connect to it.
Reverse proxy A small web server that forwards browser traffic to the backend. Caddy can expose https://translate.local while FastAPI stays on port 8000.
CUDA / cuDNN NVIDIA GPU runtime libraries for AI inference. Missing DLLs here usually mean the model cannot run on the GPU yet.
CTranslate2 The inference engine used by faster-whisper. It decides whether cuda, int8_float16, or CPU fallback is available.
VRAM GPU memory. A1000 laptops should start with small; RTX 5090 can use large-v3.
compute_type The math precision used by the model. int8_float16 saves memory on laptop GPUs; float16 fits better on the RTX server.
beam_size How many decoding paths the model compares. 1 is faster; 3 can improve text quality with more latency.
WASAPI loopback Windows system-audio capture. Needed later for Zoom, Teams, YouTube, or meeting audio without using speakers.
Models

Recommended model presets

Whisper direct translation is the simplest first version: Korean speech goes straight into English text. Add a separate Korean transcript and text translator later if you need better meaning preservation for difficult speech. On A1000-class laptops, pick the model by available VRAM first, then tune for quality.

Target Model Runtime Preset
A1000 conservative mode small faster-whisper cuda, int8_float16, beam_size=1, source transcript off
A1000 quality mode medium faster-whisper cuda, int8_float16, beam_size=1-3, only when VRAM is stable
CPU fallback base or small faster-whisper CPU int8 or whisper.cpp Lower quality and slower, useful when CUDA is unavailable
RTX 5090 LAN server large-v3 faster-whisper cuda, float16, beam_size=1-3
Avoid turbo for the first Korean-to-English translation build. OpenAI's Whisper documentation notes that turbo is not trained for translation tasks.
Some A1000 laptops ship with less VRAM than desktop/workstation A1000 cards. Run nvidia-smi first and choose small when the GPU has 4 GB or when other apps are already using memory.
A1000 laptop path

Setup for weaker local GPUs

The local laptop build should be conservative by default. The browser, Python server, VAD, and Whisper model all run on the same PC, so spare VRAM and heat matter more than peak benchmark speed.

01

Check the GPU before choosing a model

Confirm the NVIDIA driver is visible, note total VRAM, and close heavy GPU apps before testing live translation. 

nvidia-smi
python --version
02

Use the current faster-whisper CUDA path

Current faster-whisper/CTranslate2 GPU builds expect CUDA 12 libraries, including cuBLAS for CUDA 12 and cuDNN 9. If Python cannot load CUDA DLLs, fix the CUDA runtime before changing app code. 

python -m pip install --upgrade pip
pip install -r requirements.txt
python -c "import ctranslate2; print(ctranslate2.get_cuda_device_count())"
03

Start with the safe A1000 preset

This keeps latency reasonable and avoids extra memory from a second Korean transcription pass. 

$env:WHISPER_MODEL="small"
$env:WHISPER_DEVICE="cuda"
$env:WHISPER_COMPUTE_TYPE="int8_float16"
$env:WHISPER_BEAM_SIZE="1"
$env:SHOW_SOURCE_TEXT="false"
python main.py
04

Upgrade to medium only after a stable test

If small is stable for 10 to 15 minutes and translation quality is not enough, try medium with the same quantized compute type. Increase WHISPER_BEAM_SIZE only if latency is still acceptable. 

$env:WHISPER_MODEL="medium"
$env:WHISPER_DEVICE="cuda"
$env:WHISPER_COMPUTE_TYPE="int8_float16"
$env:WHISPER_BEAM_SIZE="1"
python main.py
05

Fallback when CUDA is not available

CPU mode is useful for installation checks and emergency offline use. It will usually feel slower than GPU mode, so use base first. 

$env:WHISPER_MODEL="base"
$env:WHISPER_DEVICE="cpu"
$env:WHISPER_COMPUTE_TYPE="int8"
$env:WHISPER_CPU_THREADS="8"
python main.py
If you see errors such as missing cublas64_12.dll or cuDNN DLLs, install the CUDA 12/cuDNN 9 runtime libraries or use a faster-whisper-compatible Windows runtime package. For older CUDA/cuDNN combinations, the faster-whisper README documents CTranslate2 downgrade pins.
Option A

Local-network self-hosted GPU server

This version makes the RTX 5090 PC the translation appliance. Every device on the network can open the web interface and send audio to the stronger model.

01

Prepare the server PC

Install current NVIDIA drivers, Python 3.11 or 3.12, Git, and FFmpeg. Give the PC a stable LAN address such as 192.168.1.50.

02

Create the Python backend

Use FastAPI for the HTTP app and WebSocket endpoint. Install GPU inference and audio utilities in a virtual environment. FastAPI's WebSocket guide explains the browser-to-server connection pattern. 

python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install fastapi uvicorn[standard] faster-whisper silero-vad numpy soundfile
03

Run the server on the LAN interface

Binding to 0.0.0.0 lets other devices on the network reach the backend. Uvicorn documents this through its --host setting. 

$env:WHISPER_MODEL="large-v3"
$env:WHISPER_DEVICE="cuda"
$env:WHISPER_COMPUTE_TYPE="float16"
uvicorn live_translate.app:app --host 0.0.0.0 --port 8000
04

Add HTTPS for browser microphones

Browsers allow microphone capture only in secure contexts such as HTTPS or localhost. For phones and other laptops on the LAN, place Caddy, nginx, or another TLS reverse proxy in front of FastAPI and expose wss://. Caddy is a convenient first choice because it can handle local HTTPS. 

https://translate.local
  -> FastAPI health:  http://127.0.0.1:8000/api/health
  -> FastAPI socket:  ws://127.0.0.1:8000/ws
05

Connect the web app

Open the GitHub Pages or local static frontend, enter the backend origin such as https://translate.local, then start the microphone.

Option B

Local PC app with browser interface

This is the smallest useful version. The backend, model, and UI all run on one laptop. It is easier to install, easier to debug, and works even without a network server.

01

Install the local runtime

Use the same Python backend, but start with a lighter model on laptop hardware. 

python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
02

Start in safe laptop mode

Use small first on an A1000-class laptop. Move to medium only after the safe preset is stable. 

$env:WHISPER_MODEL="small"
$env:WHISPER_DEVICE="cuda"
$env:WHISPER_COMPUTE_TYPE="int8_float16"
$env:WHISPER_BEAM_SIZE="1"
python main.py
03

Open the browser UI

Because the app is on the same machine, localhost is a secure browser context for microphone access. 

http://127.0.0.1:8000
04

Tune for speed or quality

Use base on CPU when CUDA fails. Use medium with WHISPER_BEAM_SIZE=1 when small is too rough and the GPU has headroom. 

# Fast preset
$env:WHISPER_MODEL="small"
$env:WHISPER_COMPUTE_TYPE="int8_float16"
$env:WHISPER_BEAM_SIZE="1"

# Quality preset
$env:WHISPER_MODEL="medium"
$env:WHISPER_COMPUTE_TYPE="int8_float16"
$env:WHISPER_BEAM_SIZE="1"
Audio capture

Microphone first, meeting audio second

Microphone capture is the right MVP because browser APIs handle it cleanly. Capturing Zoom, Teams, YouTube, or system audio needs desktop-level capture.

Microphone mode

Works from the browser. Best for in-person translation, a speaker near the laptop, or a meeting played through speakers.

System audio mode

On Windows, use WASAPI loopback capture in a small desktop helper. That helper can stream PCM audio to the same backend used by the browser app.

A good product path is browser MVP first, then a Windows helper for system audio and an always-on-top subtitle window.
Verification

Test checklist

Use this checklist before comparing the app against Transync AI or another polished commercial translator.

  • Audio: microphone permission opens, waveform level changes, and silence does not trigger translation.
  • Latency: normal Korean speech produces English within about 1.5 to 3 seconds on laptop mode.
  • Accuracy: compare small, medium, and server large-v3 with the same Korean sample.
  • Network: another device can open the HTTPS web app and connect to the WebSocket without mixed-content errors.
  • Recovery: unplugging the mic or losing the server connection shows a readable error and can reconnect.
  • Thermals: run for 15 minutes and watch GPU memory, fan noise, and whether latency drifts upward.
